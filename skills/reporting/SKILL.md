# Reporting

## Purpose

Communicate results, evidence, decisions, and limitations without overstating certainty.

## Core Principle

Report what happened, not what was intended to happen.

## Scope

Completion reports for discovery, execution, verification, review, and blocked work.

## Discovery

Collect final diff, test output, decisions, limitations, and unresolved findings. Prefer concrete evidence.

## Capability Requirements

Classify material capabilities as FULL, SUITABLE, CONSTRAINED, or UNSUITABLE from evidence available in the current session. Inspect actual model/agent/tool/environment availability; a documented capability is not evidence that it is callable now. Never claim an observation or verification that the available tools cannot support.

## Interaction

Only ask follow-ups when the next action needs a user decision.

## Challenge Handling

Flag discrepancies between requested and delivered outcomes; never soften a failed check into success.

## Execution Workflow

State result → changes → verification → limitations → next step. Keep recommendations distinct from completed actions.

## Verification

Cross-check report claims against actual evidence before sending.

## Reporting

Use a predictable scan-friendly structure and include remaining work.

## Completion Criteria

The report is evidence-aligned and explicit about limits.
