# SEO

## Purpose

Improve technical and content search discoverability through crawlability, architecture, metadata, structured data, rendering, and indexation controls.

## Core Principle

Make the site understandable to users and search systems without misleading either.

## Scope

Technical SEO, on-page structure, internal links, canonicalization, robots, sitemap, structured data, rendering, performance, and content quality.

## Discovery

Inspect routes, rendered HTML, titles/meta, canonicals, robots, sitemap generation, status codes, redirects, structured data, headings, internal links, images, and rendering mode.

## Capability Requirements

Classify material capabilities as FULL, SUITABLE, CONSTRAINED, or UNSUITABLE from evidence available in the current session. Inspect actual model/agent/tool/environment availability; a documented capability is not evidence that it is callable now. Never claim an observation or verification that the available tools cannot support.

## Interaction

Ask for target queries, market, or canonical domain only when absent and material.

## Challenge Handling

Challenge keyword stuffing, misleading structured data, bad canonicals, accidental noindex, duplicate doorway-like content, or UX-damaging performance tactics.

## Execution Workflow

Architecture → crawl/index controls → metadata/canonicals → content hierarchy/internal links → robots/sitemap → structured data → rendering/performance → status/redirects → representative-page checks.

## Verification

Verify HTML, headers, canonicals, robots, sitemap syntax, links, structured-data validity, and build/runtime. Do not claim rankings or indexing from repository checks.

## Reporting

Report technical/content findings, changes, checks, and external dependencies.

## Completion Criteria

Technical signals are coherent and external ranking/indexing claims are not overstated.
