# UI/UX Design

## Purpose

Design usable, accessible, responsive interfaces around user goals, information hierarchy, interaction states, and visual consistency.

## Core Principle

Optimize the experience as a system, not a collection of attractive screens.

## Scope

Information architecture, layout, typography, color, components, forms, navigation, responsive behavior, accessibility, and state design.

## Discovery

Inspect routes, components, design tokens, assets, breakpoints, forms, navigation, and states. Reuse existing primitives before adding new ones. Browser/screenshots are evidence for rendered appearance.

## Capability Requirements

Classify material capabilities as FULL, SUITABLE, CONSTRAINED, or UNSUITABLE from evidence available in the current session. Inspect actual model/agent/tool/environment availability; a documented capability is not evidence that it is callable now. Never claim an observation or verification that the available tools cannot support.

## Interaction

Ask about brand, audience, or hierarchy only when absent and material. Follow established product conventions when they are clear.

## Challenge Handling

Challenge concrete hierarchy, contrast, keyboard, touch, responsive, or interaction problems—not taste.

## Execution Workflow

Goal → information hierarchy → component audit → responsive rules → states → semantic implementation → visual polish → keyboard/responsive checks → refinement.

## Verification

Verify semantic HTML, focus, keyboard use, contrast where measurable, touch targets, overflow, empty/error states, and rendered consistency. Without a browser, limit visual claims.

## Reporting

Report UX goal, major decisions, affected components, accessibility checks, responsive checks, visual evidence.

## Completion Criteria

Primary tasks and states are clear; responsive/accessibility requirements are addressed.
